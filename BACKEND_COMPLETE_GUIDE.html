RentHub Backend - Complete Guide

Last Updated: May 16, 2024 | Status: Production Ready ✅

🚀 QUICK START

cd backend
go run cmd/renthub/main.go
# Server: http://localhost:8080

📊 PROJECT OVERVIEW

RentHub Backend is a Go REST API for a peer-to-peer rental marketplace.

Tech Stack: - Language: Go 1.23 - Framework: Gin Web Framework - Database: PostgreSQL 12+ - ORM: GORM - Auth: JWT (HS256) + bcrypt

Key Stats: - 25+ API Endpoints - 7 Database Tables - ~3,500 Lines of Code - Full CRUD Operations - Real-time Messaging

🏗️ ARCHITECTURE

Frontend (React)
    ↓ HTTP/JSON
Gin Router (Port 8080)
    ├─ CORS Middleware
    ├─ Auth Middleware (JWT validation)
    └─ Route Handlers
        ├─ auth.go (Signup/Login)
        ├─ items.go (Item CRUD, Search, Reviews)
        └─ rentals.go (Rentals, Messages, Wishlist)
            ↓ SQL Queries (GORM)
PostgreSQL Database (7 Tables)

🔐 AUTHENTICATION

Flow: 1. User sends: POST /api/auth/signup → System hashes password (bcrypt, cost=10) 2. System generates JWT token (expiration: 7 days) 3. Client stores token in localStorage 4. Each request: Authorization: Bearer {token} 5. AuthMiddleware validates token → extracts user_id → handler proceeds

JWT Claims: { user_id, email, exp: now+7days }

Bcrypt: Password hashed with random salt, never stored plain-text

🔄 RENTAL WORKFLOW

Rental Request States:
pending ──[owner approves]──> approved ──[creates Rental]──> item unavailable
    └──[owner rejects]──> rejected ──> item remains available

Rental States:
active ──[end date reached]──> completed
     └──[cancelled]──> cancelled

📋 CORE MODULES EXPLAINED

1. Authentication (auth/jwt.go)

GenerateToken(user User) → string - Creates JWT with user_id, email, exp=now+7days - Signed with HS256 algorithm - Used after signup/login

**VerifyToken(tokenString) → *CustomClaims, error** - Parses and validates JWT signature - Checks expiration - Returns user_id and email - Called by AuthMiddleware

HashPassword(password) → string - Bcrypt hash with salt (cost=10) - Takes ~100ms per hash - Only stored hash, never plain-text

ComparePasswords(hash, password) → error - Verifies password matches bcrypt hash - Returns nil if match, error if mismatch - Used during login

2. Database (database/db.go)

InitDB() → error - Connects to PostgreSQL - Runs AutoMigrate for all models - Creates/updates tables - Stores connection in global DB variable

**GetDB() → *gorm.DB** - Returns global database instance - Used by handlers for queries

3. Handlers (Business Logic)

auth.go

  • Signup: Validate request → Hash password → Create user → Generate token
  • Login: Find user by email → Verify password → Generate token

items.go

  • GetItems: Return all items
  • GetItemsByCity: Filter items by city (with fallback to all)
  • GetItemByID: Get single item details
  • CreateItem: Validate → Set owner/location from user → Create
  • UpdateItem: Verify ownership → Update → Save
  • DeleteItem: Verify ownership → Delete
  • SearchItems: Filter by name/category and city
  • CreateReview: Validate rating → Create review → Update item.rating
  • GetReviews: Return reviews ordered by newest first
  • updateItemRating: Recalculate average rating after new review

rentals.go

  • AddToWishlist: Create user’s saved item
  • GetWishlist: Get user’s saved items
  • RemoveFromWishlist: Delete saved item
  • RentItem: Create rental request (status=pending)
  • GetMyRentals: Get user’s active rentals
  • GetIncomingRentalRequests: Requests to rent my items (owner view)
  • GetOutgoingRentalRequests: Requests I sent (renter view)
  • ApproveRentalRequest: Create rental → Mark item unavailable
  • RejectRentalRequest: Reject request → Keep item available
  • SendMessage: Send message in rental request conversation
  • GetRentalRequestMessages: Get all messages, mark as read
  • GetMyItems: Get items owned by user
  • GetUserProfile: Get user account info

4. Middleware (middleware/auth.go)

AuthMiddleware(): - Validates Authorization: Bearer {token} header - Parses token format - Verifies JWT signature & expiration - Extracts user_id and email → stores in context - Returns 401 if invalid

CORSMiddleware(): - Sets Access-Control-Allow-Origin: * - Allows all HTTP methods (GET, POST, PUT, DELETE) - Allows Authorization header - Responds 204 to OPTIONS (pre-flight)

5. Models (Data Structures)

User: id, name, email, password (hash), city, pincode, lat/long

Item: id, owner_id, name, category, description, price, image, available, rating, reviews, lat/long

Rental: id, item_id, renter_id, owner_id, start_date, end_date, status, total_cost

RentalRequest: id, item_id, renter_id, owner_id, dates, status, message, rental_id

Message: id, rental_request_id, sender_id, receiver_id, content, is_read

Review: id, item_id, user_id, rating, comment

Wishlist: id, user_id, item_id

🌊 DATA FLOW EXAMPLES

Signup Flow

POST /api/auth/signup
├─ Validate JSON
├─ Check passwords match
├─ HashPassword() → bcrypt hash
├─ DB CREATE user {name, email, hash, city, lat, long}
├─ GenerateToken(user) → JWT
└─ Return {token, user{id, name, email}}

Create Item Flow

POST /api/items (with Authorization header)
├─ AuthMiddleware → validate token → extract user_id
├─ CreateItem handler
├─ Validate request JSON
├─ DB SELECT user WHERE id = user_id
├─ Set item.owner_id = user_id
├─ Set item.city, lat, long from user
├─ Set item.available = true
├─ DB INSERT item
└─ Return created item

Rental Request Flow

POST /api/rentals (with token)
├─ AuthMiddleware → user_id (renter)
├─ Validate dates
├─ DB SELECT item → check owner_id ≠ renter_id
├─ DB INSERT rental_request {status: "pending"}
└─ Return request

Then owner:
POST /api/rentals/requests/{id}/approve
├─ AuthMiddleware → user_id (owner)
├─ Verify ownership
├─ Calculate: days = (end_date - start_date)
├─ Calculate: cost = days × item.price
├─ DB INSERT rental {status: "active", cost}
├─ DB UPDATE rental_request {status: "approved"}
├─ DB UPDATE item {available: false}
└─ Return rental

Message Flow

POST /api/messages (with token)
├─ Validate request
├─ DB SELECT rental_request
├─ Verify sender is owner OR renter
├─ Determine receiver (other party)
├─ DB INSERT message {sender_id, receiver_id, content}
└─ Return message

Later:
GET /api/messages/rental-request/{id}
├─ DB SELECT messages WHERE rental_request_id = id
├─ Order by created_at ASC
├─ DB UPDATE messages SET is_read = true
└─ Return messages

🐛 ERROR CODES & HANDLING

Code Reason Example
200 OK Get, Update success
201 Created Signup, Create item
400 Bad Request Missing fields, validation fail
401 Unauthorized No/invalid token
403 Forbidden Not owner, trying to delete another’s item
404 Not Found Item/user doesn’t exist
500 Server Error Database error, hash failure

Error Response Format:

{"error": "descriptive message"}

🚀 DEPLOYMENT

Local Development

# 1. Start PostgreSQL
brew services start postgresql

# 2. Create database
psql -U postgres -f renthub.sql

# 3. Run backend
cd backend
go run cmd/renthub/main.go

Environment Variables (Production)

DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_password
DB_NAME=renthub
JWT_SECRET=your-secret-key-min-32-chars
PORT=8080

Docker

docker build -t renthub-backend .
docker run -p 8080:8080 -e DB_HOST=postgres renthub-backend
